# v5 Improvement Plan: RUL Trend per Fault Family, 916 Air-Filter Labels

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the two root causes the 2026-10-17 gaps plan found:
- the W2 logbook trend drags RUL to the calendar cap on faults the logbook cannot see grow (915 turbo_high);
- 916 air-filter recall is 0.33 on test.

Ship an engine only if it beats its live model.

**Architecture:**
- **Track R (cheap):** the RUL model only. `TrendGatedRUL` learns, per fault family on validation flights, whether the trend helps. Only `--force rul,test,card` reruns (about 15 min per engine). Severity and diagnosis stay untouched, so nothing else moves.
- **Track L (expensive, gated by a measurement):**
  - If most 916 air-filter misses are windows where no instrument shows the fault above its healthy spread, the labels are wrong, not the network. Relabel with the existing per-instrument rule (`relabel_v5b.py --per-channel-faults`) and retrain the 916's five specialists (about 12 h).
  - Otherwise, retrain the diagnosis network only, with a heavier air-filter loss (about 3 h).

**Tech Stack:** Python 3.11 + TensorFlow-metal (`validation/venv`); scikit-learn; `validation_v5/` pipeline; `backend/` live stack.

**Spec:** the outcome of `docs/superpowers/plans/2026-10-17-v5-model-gaps.md` (Tasks 3 and 5) and Harsh24856/Aero-Sim#26.

## Global Constraints

- **Gates:** `validation_v5/gates_v5.py` bars are unchanged. Nothing is chosen on the test split.
- **Acceptance:** an engine's new export ships only if both hold:
  1. `scripts/ab_v5.py --engine <e> --old origin/main --new .` prints `A/B RULE: PASS`, or every rule is at least equal and the targeted metric improves;
  2. no test-card gate goes from PASS to FAIL.

  Otherwise the export is restored with `git checkout origin/main -- backend/models_v5/<e>`.
- **One GPU job at a time.** Run under `caffeinate -is`, with the lid open and on mains power.
- **Exports from a clean tree:** commit the artifacts first, so the manifest records `git_dirty: false`.
- **After merging:** update the main checkout (`git pull --ff-only`) and restart `scripts/start_stack.sh`.

## Review Focus

1. **A window with no confident family** (all family probabilities low): the trend rule must fall back to the base RUL, not use the trend.
2. **An engine where validation allows every family:** the RUL output must equal today's `gated_gbt+trend0.5` exactly, with no regression by construction.
3. **The 916 has no trend today** (`gated_gbt` was chosen): Track R must leave it unchanged unless validation now picks a family-gated trend.
4. **Relabel moves every engine-fault label on the 916:** the old and new cards are not comparable. Only the A/B, which flies label-independent truth, decides.
5. **The 914 passes 6/6:** Track R may refit it, but it ships only on an A/B win.

### Task 1: Family-gated logbook trend in RUL (Track R)

**Files:**
- Modify: `validation_v5/rul_v5.py` (`TrendGatedRUL`, and `fit_rul`'s candidates)
- Test: `validation_v5/tests/test_rul_history_v6.py`

**Interfaces:**
- Produces:
  - `TrendGatedRUL(gated, weight: float, families: tuple[int, ...] | None = None, fam_cols: slice | None = None)`.
    - `families=None` keeps today's behaviour exactly.
    - Otherwise the trend is used only where the window's argmax family index is in `families` and that family's probability is at least 0.5.
  - `family_cols(n_faults: int, n_families: int) -> slice`: the slice of `rul_inputs` columns holding `o["family"]`. That is `slice(n_faults + 2, n_faults + 2 + n_families)`, because the layout is health(1), severity(n_faults), engine_fault(1), family.
  - `fit_rul` adds one candidate, `gated_gbt+trend{w}+fam`, for the w that won among the trend candidates. Its `families` are those whose validation wear-limited MAE is lower with the trend than without it, judged on the validation windows of that family. The existing validation rule then picks among all candidates.

**Interfaces:**
- Produces:
  - `recall_by_bin(y: np.ndarray, pred: np.ndarray, values: np.ndarray, edges: list[float]) -> list[dict]`. It returns `{"lo", "hi", "positives", "recall"}` per bin, with `recall=None` when a bin has no positives.

    - altitude.
